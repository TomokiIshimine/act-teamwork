# help — act-core の使い方

引数 `$ARGUMENTS` が空なら下の 3 つの表をすべて示す。コマンド名や状況が書かれていれば、該当する行だけを示す。案内だけを行い、ファイルの読み書き、設定の変更、コマンドの実行はしない。

## コマンド一覧

| コマンド | いつ使う | 何をする |
| --- | --- | --- |
| `/act-core:setup [プロジェクト名] [共有フォルダのパス] [保存先のURL]` | 初めて使うとき、新しいプロジェクトを始める・参加するとき、既存の Notion ページを ACT 用にするとき、プラグインを更新した後 | 個人設定 `~/.act/config.yaml` にプロジェクトを 1 件追加し、保存先（Notion の DB 一式など）を新規作成・取り込み・更新する。書く前に 2 回の確認フォームで承認を取る |
| `/act-core:help [コマンド名や状況]` | 使い方が分からないとき | この案内を表示する |

`act-core:store-protocol` と `act-core:write-plan` は、ほかのスキルとエージェントが読む規約で、直接呼ぶものではない。

## 初めて使うときの流れ

| 順 | すること | 補足 |
| --- | --- | --- |
| 1 | `act-core` と、保存先のアダプタ（Notion なら `act-store-notion`、共有フォルダなら `act-store-localfs`）を入れる | アダプタが無いと、初期設定は変更計画の段階で止まる |
| 2 | 保存先のコネクタ（Notion など）を自分のアカウントで接続する | 保存先には本人の接続で書く。認証情報はファイルに書かない |
| 3 | Cowork では、`~/.act/` とプロジェクトの共有フォルダ（Google ドライブの同期先など）をフォルダ接続する | Claude Code ではローカルのパスをそのまま使う |
| 4 | `/act-core:setup` を実行する | 新しいプロジェクトを作るのはマネージャー（またはビジネスオーナー）。メンバーは作成済みのプロジェクトに参加する |

## 困ったとき

| 状況 | 対処 |
| --- | --- |
| 「保存先の作成・取り込み・更新は作成者だけ」と言われて止まった | プロジェクトのマネージャーに保存先の作成を依頼する。作成後に共有フォルダの `.act/project.yaml` ができたら、もう一度 `/act-core:setup` で参加する |
| 「アダプタが無い」と言われた | 保存先の種類に合うアダプタのプラグインを入れて再実行する |
| スキーマ版が古いと警告された | マネージャーが `/act-core:setup` を再実行すると、保存先の更新を計画できる |
| 接続先のワークスペースが違うと言われた | 保存先のコネクタを、そのプロジェクトのワークスペースにつなぎ直す |
| 途中で失敗した | 同じ共有フォルダで `/act-core:setup` を再実行すると、前回の未完了の実行を見つけて、成功した項目を飛ばして続きから進める |
| 保留した項目をあとで書きたい | `/act-core:setup` を再実行すると、保留した項目が変更計画に再び載る |
