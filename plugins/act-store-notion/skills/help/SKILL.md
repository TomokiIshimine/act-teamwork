# help — act-store-notion の使い方

引数 `$ARGUMENTS` が空なら下の表をすべて示す。状況が書かれていれば、該当する行だけを示す。案内だけを行い、Notion・ファイル・設定には触らない。

## このプラグインがすること

| 項目 | 内容 |
| --- | --- |
| 役割 | ACT の保存先アダプタ。決定事項・タスク・ナレッジ・アーティファクトのメタ情報・実行ログ・ワークフロー設定・メンバー・タグなどを Notion の DB に置く |
| 使われ方 | 直接呼ぶものではない。`act-core` のワークフロー（`/act-core:setup` など）が `act-store-notion:store` を読んで使う |
| 書き込み | 本人の Notion コネクタで書く。権限の無い操作は Notion が拒否し、ワークフローは警告にして飛ばす |
| 保存先の版 | 版 1 の保存先（トップページの本文に ACT 設定がある）は、マネージャー（またはビジネスオーナー）が `/act-core:setup` を実行すると、更新で版 2 に移せる |

## 初めて使うときの流れ

| 順 | すること | 補足 |
| --- | --- | --- |
| 1 | `act-core` と `act-store-notion` を入れる | 共有フォルダにアーティファクト本体を置くなら `act-store-localfs` も入れる |
| 2 | Notion コネクタを自分のアカウントで接続する | プロジェクトのワークスペースにつなぐ |
| 3 | ACT 用のページ（親ページ）を Notion に作り、その URL を控える | 既存のページを ACT 用にすることもできる（取り込み） |
| 4 | マネージャーが `/act-core:setup <プロジェクト名> <共有フォルダ> <親ページの URL>` を実行する | DB 一式の作成計画が示され、承認後に作られる |
| 5 | 計画に出た「手作業が必要な設定」を Notion で行う | 下の表 |

## Notion での手作業の設定

| 対象 | 設定 |
| --- | --- |
| 👥 メンバー | マネージャー・ビジネスオーナー「編集可」、他メンバー「コメント可」。参加者は自分を `worker` で登録し、役割はマネージャーが設定する |
| 🧠 ナレッジ | DB 全体をメンバー「コメント可」、行単位の権限ルールで「所有者に一致 → 編集可」（プランによっては使えない） |
| 🗂 決定事項 | マネージャー・ビジネスオーナー「編集可」、他メンバー「コメント可」 |
| ⚙️ ワークフロー設定 | マネージャー「編集可」、他メンバー「コメント可」。辞書のページだけ全員「編集可」 |
| 🏷 タグ | 全メンバー「編集可」（削除はしない決まり） |
| 🧾 実行ログ | 全メンバー「編集可」 |
| 🔧 ACT 設定 | マネージャー・ビジネスオーナーだけ「編集可」 |
| 各 DB | 本文テンプレートを Notion の DB テンプレートとして登録する |

## 困ったとき

| 状況 | 対処 |
| --- | --- |
| 「Notion コネクタが接続されていない」と言われた | コネクタの設定で Notion を接続し直す |
| 「接続先のワークスペースが違う」と言われた | Notion コネクタを、そのプロジェクトのワークスペースにつなぎ直す |
| 権限が無いと警告された | そのページ・DB の共有設定を確認する。決定事項など役割で制限している DB は、マネージャーに依頼する |
| 「移行中」で止まった | 他の人の `/act-core:setup` の適用が終わるのを待つ。止まったままなら、トップページの子ページ 🔧 ACT 設定と 🧾 実行ログをマネージャーが確認する。1 時間以上たっても止まったままなら、マネージャーが `/act-core:setup` を再実行し、変更計画フォームで「印を外して続きから適用する」を選ぶ |
| DB の名前やプロパティを手で変えた | 説明文 1 行目の `[ACT]` の印は消さない。プロパティ名を変えた場合は `/act-core:setup` の取り込みで対応づけ直す |
