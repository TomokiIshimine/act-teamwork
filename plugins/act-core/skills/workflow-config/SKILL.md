# workflow-config — ワークフロー設定の読み込み・重ね合わせ・追加候補

ワークフロー設定は、プロジェクトとしてこう処理するという共有の決め事（辞書・ルール・書式・参照情報）。各ワークフローは、プラグイン同梱の既定の上にプロジェクトの設定を重ねて使い、どの設定のどの版を使ったかを出力に残す。保存先への読み書きは `act-core:store-protocol`、ローカルのファイルの読み書きは `act-core:local-files` に従う。

呼び出し元が渡すもの:

- `workflow`: 対象のワークフロー ID（`C1`、`C2`、`M6` など）
- 対象プロジェクトの `project.yaml` の `stores.workflow_config`（無ければ無し）と、その `mapping`
- `output_path`: 重ねた結果の書き出し先（絶対パス）

## 読み込み

次の順に集める。

1. **既定**: act-core のプラグインのルート直下の `defaults/`（このスキルから見て `../../defaults/`）のファイルのうち、属性 `workflows` に `workflow` か `全ワークフロー` を含むもの。ファイルの形は `defaults/README.md` に従う（先頭の YAML が属性、`##` 見出しが本文のセクション）。`README.md` 自体は設定として読まない。
2. **プロジェクト**: 保存先の `workflow_config` を `query`（`filter`: `status: 有効`、対象ワークフローが `workflow` か `全ワークフロー`）し、該当した各件を `get` で取って本文を得る。`下書き`・`無効` は読まない。

- `stores.workflow_config` が無いとき、またはアダプタが `workflow_config` 型に対応していないとき（`describe` の `types`）は、既定だけを使い、警告に「プロジェクトのワークフロー設定が無いので既定だけを使った」と残して呼び出し元へ返す。
- `query`・`get` が正準エラーを返したときは `act-core:store-protocol` の扱いに従う。読めなかった件は重ねずに警告に残す。

## 重ね方

後に読んだもの（プロジェクト）が優先する。

| `kind` | 重ね方 |
| --- | --- |
| `辞書` | 本文の表を行単位で合成する。「誤記と正記」は「誤記」をキーに、同じ誤記はプロジェクト側の行が勝つ。辞書の他の表（「話者名の対応」など）も先頭列をキーに同じく合成する |
| `抽出・判断ルール`、`書式テンプレート`、`参照情報` | `kind` と `name` が同じ設定がプロジェクト側にあれば、既定をまるごと置き換える。無ければ両方を使う |

- 既定のひな形で先頭列が「（例）」で始まる行は、例示なので重ねた結果に入れない。
- プロジェクト側に同じ誤記で正記が違う行が複数あるとき（別の辞書どうし）は、更新日時の新しい設定の行を使い、警告に残す。
- 「文脈で判断」の印は行ごとに引き継ぐ。印のある行を自動で置き換えるかは、各設定の「使い方」に従う。

## 書き出し

`output_path` に Markdown で次の見出しを書く。呼び出し元はこのファイルを読んで処理する。

```markdown
# ワークフロー設定（<workflow>）

## 使った設定

| id | name | kind | version | 出どころ |
| --- | --- | --- | --- | --- |
| default:term-dictionary.md | 用語・表記辞書 | 辞書 | 1 | 既定 |
| FAQ-CFG-1 | 用語・表記辞書 | 辞書 | 3 | プロジェクト |

## 辞書

<表ごとに `###` 見出し。合成した行に列「出どころ」（設定の id）を足す>

## ルール・書式・参照情報

<設定ごとに `### <name>（<id> 版 <version>）` とその本文>

## 警告

<無ければ「なし」>
```

- `id` は、既定なら `default:<ファイル名>`、プロジェクトなら保存先の ID。置き換えられて使わなかった既定は表に入れない。
- 呼び出し元は「使った設定」の `id` と `version` を、出力（アーティファクトのメタ情報、実行ログなど）の出典に残す。

## 辞書への追加候補

呼び出し元は、入力の中で重ねた辞書に無い誤変換らしい語を、出典の位置つきで「辞書への追加候補」として書き込み計画に載せる。勝手に追記しない。項目の形・確信度・確認の取り方は `act-core:write-plan` に従う。

- 1 候補の内容: 誤記、正記の案、「文脈で判断」の要否、出典（アーティファクト・版・位置）、追加先（設定の `id`・`name`・現在の `version`）。
- 追加先は、対象プロジェクトの `kind: 辞書` で、使った辞書と同じ `name` の設定（`status` は問わない）。プロジェクト側に無い（既定だけを使った）ときは候補を計画に載せず、警告に「追加先の辞書がプロジェクトに無い」と残す。新しい設定は作らない。
- 正記が入力から 1 つに決まらない候補は、正記を空にして確信度を低にする。

## 追加候補の反映

書く役は、確認で採用された候補だけを反映する。

1. 追加先の設定に `update` で、本文の「誤記と正記」の表（既定の形では「中身」セクションの中）に採用した行を `append` する。既存の行は変えない。同じ誤記の行が既にあれば追記せず、結果に「既にある」と残す。
2. 同じ `update` で属性 `version` を 1 上げる。
3. 「変更履歴」セクションに `append` で 1 行足す: `- 版 <新しい版>: <日付> 辞書に <行数> 行を追記（run_id: <run_id>）`。

採用が 0 件なら何もしない。保留した候補は `act-core:write-plan` の「答えの反映」に従って実行ログに残す。

## 権限

- 判定は `act-core:permission-gate`（`config_dictionary_append`・`config_rule_change` の行）に従う。保存先で拒否されたら `act-core:store-protocol` の `permission_denied` の扱いに従う。
