# artifact-placement — 置き場所と索引

アーティファクト本体は、共有ルートの中の **置き場所**（目的を持つ階層の入れ物）に、内容（テーマ）ごとに整理して置く。各置き場所には **索引**（直下のファイルと置き場所の一覧）を持たせ、人が置き場所を開いたときに中身と状態が分かるようにする。

この規約は保存先に依らない概念だけを扱う。置き場所と索引の実体（保存先での入れ物の形、索引の書式と置き方）はアーティファクト本体のアダプタが持つ。置き場所の読み書きは `act-core:store-protocol` の操作（`list_folders`・`create_folder`・`update_index`、`put_file` の `fields.folder`）で依頼し、アダプタを通さずに作らない。`project.yaml` の読み書きは `act-core:local-files` に従う。

役割の分担:

- 計画を作る役: 構成を読み、置き場所を選び（初回は構成案、合う場所が無ければ新しい置き場所の案）、索引の更新とあわせて書き込み計画（`act-core:write-plan`）の項目にする。保存先は読むだけ。
- 書く役: 採用された項目だけを、構成の設定 → 置き場所の作成（親から順）→ 本体の配置 → メタ情報 → 索引の更新 の順に適用する。

どのワークフローのどの段で使うか、項目の ID・ファイル名は各ワークフローの定めを正とする。

## 構成の読み取り

構成の状態は次の 3 つのどれか。上から順に判定する。

| 状態 | 条件 | 扱い |
| --- | --- | --- |
| `unsupported` | アーティファクト本体のアダプタの `describe` の `ops` に `list_folders`・`create_folder`・`update_index` のどれかが無い | 置き場所と索引の項目を作らない。`layout` の従来の固定パスに置き、アダプタの更新を促す警告を出す |
| `configured` | `stores.artifact_body` に `folder_root` があり、`layout` が `{folder}` を使う | `list_folders` で木を読む |
| `unconfigured` | 上のどちらでもない（初回） | 初回の構成案を作る（下記）。警告にはしない |

- `configured` のとき、`list_folders`（`root`・`folder_root`）で各置き場所の相対パス・目的の 1 行・直下のファイル数と置き場所の数を読む。
- 各置き場所の目的は索引が正。設定ファイル（`project.yaml`）にもワークフロー設定にも写さない。

## 初回の構成案

構成が `unconfigured` のとき、置き場所を必要とするワークフローが初回の構成案を作り、確認要の項目として書き込み計画に載せる。位置は、対象プロジェクトの確認項目があればその次、無ければ先頭にする。作り方の詳細と例は `references/initial-structure.md` を読む。要点:

- 根は `folder_root`（既定 `library`）。共有ルート直下の 1 つの置き場所とし、その下に木を作る。
- 第 1 階層は 3〜7 個。各置き場所に目的を 1 行で書く。
- 材料: プロジェクトの名前・クライアント、既存のタスクと 📄 アーティファクトの名前（`query`）、今回のファイルの内容。
- 第 2 階層は今回のファイルを置くのに要るものだけ作る。それ以外は以後の実行で必要になったときに足す。
- 空の第 1 階層の置き場所は作ってよい（目的が次回の振り分け先になる）。
- `layout` は次のとおりにする。`minutes` など、ほかのキーは変えない。

  ```yaml
  folder_root: library
  layout:
    input: library/{folder}/{title}{ext}
    working: library/{folder}/{title}{ext}
    deliverable: library/{folder}/{title}_{version}{ext}
  ```

  `{folder}` は `folder_root` からの `/` 区切りの相対パス。`folder_root` を変えたときは各行の先頭もそれに合わせる。
- 構成を設定する前に従来の固定パスに置かれたファイルは動かさない。

## 置き場所の付け方

- テーマ（内容）で分ける。用途・日付・人名・状態では分けない。用途は版の規則（`layout` のキー）で、状態は索引とメタ情報で表す。
- 名前は別の資料にも使える一般名詞の日本語にする。ファイル名に使えない文字（`/ \ : * ? " < > |`）を使わない。
- 深さは根から 3 階層まで。
- 新しく作る前に、名前と目的で既存の置き場所を探す。近いものがあればそこを使う。
- 同じ置き場所の直下が 15 件を超えたら、第 2 階層に分ける案を警告として示す。ファイルの移動はしない。

## 置き場所の選択

ファイルの内容と各置き場所の目的を照合して 1 つ選ぶ。呼び出し元の指定（利用者の修正 `overrides` など）があればそれを正とし、確信度 高にする。

| 確信度 | 基準 |
| --- | --- |
| 高 | 目的に明らかに合う置き場所が 1 つある |
| 中 | 合う候補が 2 つ以上ある。候補と推奨を添える |
| 低 | 合うものが無い。新しい置き場所の案（相対パスと目的）を出す |

確信度の付け方と既定の採否は `act-core:write-plan` に従う。

## 索引の行の値

索引は置き場所の直下にある 1 件ごとに 1 行を持つ。行の形（キーと型）は `act-core:store-protocol` の `update_index` に従い、ここでは置き場所に固有の値の入れ方だけを定める。

| キー | 入れる値 |
| --- | --- |
| `name` | ファイルは本体の配置（`put_file`）の戻り値の `location` の最後の要素（別名で置いたときはその名前）。置き場所はその名前 |
| `summary_line` | ファイルは 📄 アーティファクトの 1 行要約、置き場所はその目的 |
| `kind` | ファイルは 📄 アーティファクトの `kind`。置き場所は空 |
| `status` | 📄 アーティファクトの `status`。作業途中のファイルは「作業途中」と分かるようにする |
| `version` | 版付きの写しはその版 |
| `meta_url` | メタ情報の `create`／`update` の戻り値のページ |

- ほかのキーは `act-core:store-protocol` の定義どおりに入れる。
- 索引は 📄 アーティファクト（メタ情報）の写し。食い違えばメタ情報が正。
- 行は `name` で足す・置き換える。索引のほかの部分（人が書いた目的の説明やメモ）は変えない。

## 索引を更新する場面

どのワークフローでも、次のどれかを変えたら、同じ実行で `update_index` を書き込み計画に載せる。

- ファイルを置いた・上書きした・版付きの写しを作った置き場所
- 新しく作った置き場所の親
- 📄 アーティファクトの `status`・`version`・`summary_line` を変えたファイルの置き場所

行の値は「索引の行の値」のとおり、計画の推定ではなく適用の結果（`put_file` とメタ情報の戻り値）で埋める。索引の更新が失敗しても本体とメタ情報は正なので、実行を止めずに「索引が古いまま。次回の更新か再実行で直る」と警告する。

## 版の残し方との関係

- 作業途中のファイルと版付きの写しは同じ置き場所に並べる。索引では版付きの写しに版を、作業途中のファイルに「作業途中」を示す。
- 同じ置き場所の同名ファイルを上書きしてよいのは、そのパスの既存の 📄 アーティファクトの `usage` に `作業途中` があるときだけ。それ以外（入力の原本、版付きの写し、メタ情報の無いファイル）と同名になるときは、名前に用途を表す語を足して別名にする。

## 権限

判定は `act-core:permission-gate` に任せる（既定は同スキルの `references/default-policy.md` の `## 置き場所` の `placement_structure`・`placement_folder_add`・`placement_index_update`・`placement_folder_modify` の行）。ここでは判定の結果に応じた置き場所に固有の扱いだけを定める。

- 既存の構成への置き場所の追加は、許されるときも確認要の項目にする。
- 構成を設定する権限が無いときは、構成案を書いた判断依頼（宛先 マネージャー）にし、今回のファイルは従来の固定パスに置く。
- 置き場所の改名・移動・削除は計画しない（下記「してはいけないこと」）。

## 出力の形

計画を作る役は、次の形で結果を持つ。どのファイルのどのキーに書くかは呼び出し元が決める。

- 構成案: `{ folder_root, layout, folders: [{ path, purpose, create: true|false }] }`
- 置き場所の選択: `{ file_id, folder, confidence, reason, new_folder?: { path, purpose } }`
- 索引の更新: `{ folder, upsert: [<行>] }`（行の形は `act-core:store-protocol` の `update_index`、値は「索引の行の値」）

## してはいけないこと

- 置き場所の改名・移動・削除、既存ファイルの移動を計画しない・依頼しない。
- 置き場所の目的を設定ファイルに写さない（索引が正）。
- アダプタを通さずに置き場所や索引を作らない・書き換えない。
