# help — act-store-localfs の使い方

引数 `$ARGUMENTS` が空なら下の表をすべて示す。状況が書かれていれば、該当する行だけを示す。案内だけを行い、ファイル・設定には触らない。

## このプラグインがすること

| 項目 | 内容 |
| --- | --- |
| 役割 | ACT の保存先アダプタ。議事録の原文（文字起こし）・入力資料・作業途中のファイル・成果物などのアーティファクト本体を、プロジェクトの共有フォルダ（Google ドライブ等の同期先）に置く。メタ情報は Notion 側（`act-store-notion`）に置く。議事録の清書は Notion の 📝 議事録の本文に置く |
| 使われ方 | 直接呼ぶものではない。`act-core` のワークフローが `act-store-localfs:store` を読んで使う |
| 安全 | 共有フォルダの外には書かない。ファイルを削除しない。上書きするのは作業途中（`work/`）のファイルだけで、議事録・入力・成果物は同じ名前があれば別名か新しい版にする |

## 共有フォルダの構成

| フォルダ | 置くもの | ファイル名 |
| --- | --- | --- |
| `minutes/` | 元の場所が無い議事録の原文（貼り付け・共有ルート外の添付）。ドライブ・Notion・Slack にある原文は写さない | `<日付>_<タイトル>_原文<拡張子>` |
| `inputs/<種類>/` | 要望書・データなどの入力 | `<タイトル><拡張子>` |
| `work/` | 作業途中のファイル | `<タイトル><拡張子>` |
| `deliverables/` | 成果物 | `<タイトル>_<版><拡張子>` |
| `library/<テーマ>/…` | テーマ別の置き場所。入力・作業途中・成果物を内容（テーマ）ごとのフォルダにまとめて置く（構成の設定後） | 用途ごとの規則（上と同じ） |
| `.act/` | ACT の設定（`project.yaml`）とこのアダプタの記録 | 手で編集しない |

以前の版で `minutes/` に置いたファイルは動かさない。

配置の規則はプロジェクト設定 `.act/project.yaml` の `stores.artifact_body.layout` で変えられる。

テーマ別の置き場所（`library/` の下）は、初めて `/act-core:ingest-file` でファイルを取り込むときに構成案が示され、承認後に作られる（根の名前は `stores.artifact_body.folder_root`）。各階層に `README.md` があり、そのフォルダの目的と直下の一覧（内容・種類・状態・版・更新日・メタ情報）を持つ。README の一覧の表は ACT が更新するので、メモは表の外（`## メモ`）に書く。構成の設定前に `inputs/` などに置いたファイルは動かさない。

## 初めて使うときの流れ

| 順 | すること | 補足 |
| --- | --- | --- |
| 1 | `act-core` と `act-store-localfs` を入れる | |
| 2 | プロジェクトの共有フォルダを用意し、PC で同期しておく | Google ドライブの共有ドライブなど |
| 3 | Cowork では、共有フォルダをフォルダ接続する | Claude Code ではローカルのパスをそのまま使う |
| 4 | `/act-core:setup` を実行する | フォルダ構成の作成計画が示され、承認後に作られる |

## 困ったとき

| 状況 | 対処 |
| --- | --- |
| 共有フォルダに書けないと言われた | Cowork ならフォルダ接続を確認する。読み取り専用で接続されていないか、同期が止まっていないかを確かめる |
| 同じ名前の成果物があると言われた | 成果物は上書きしない。版を上げて保存し直す |
| 作業途中のファイルが編集されていると言われた | AI が前に読んだ後に人が編集している。最新の内容を読み直してから保存し直す |
| README の一覧が古い | 次の取り込みで直る。手で直してもよいが、一覧の表は ACT が上書きする（メモは表の外に書く） |
| 作業途中のファイルが上書きされず conflict になった | 前に取り込んだときから人が編集している。最新の内容を確かめてから取り込み直す |
| 既存のフォルダ構成を使いたい | `/act-core:setup` の取り込みで、既存のフォルダを議事録・入力などに対応づける |
